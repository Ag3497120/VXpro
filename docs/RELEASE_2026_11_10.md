# Controller / tracked-hand integration — 2026-11-10

This update brings the accumulated `hand-tracking` work and subsequent local changes into `main`,
at the developer's request. It includes the previous performance, camera, vehicle and direct CDPR
cloud-save checkpoint. It does not reset settings, saves or accounts on an installed headset.

## Controls and presentation

- Hold Joy-Con **+ and − together for one second** to switch between tracked-hand weapon interaction
  and the game's normal controller weapon handling. Release both to rearm. Single presses retain
  their menu action; a recognized chord does not open either menu.
- The switch releases synthetic held input, waits for neutral gameplay buttons and the script's
  ownership acknowledgement, cancels pending manual commands and starts a new tracked-pose epoch.
  Both modes retain head tracking. Switching does not refill ammunition or rewrite inventory.
- Controller mode restores native palette bindings and native reload behavior. The tracked mode
  resumes its existing weapon adapter. `VXMAC_CONTROL_MODE=controller` selects the initial mode.
- Quick-menu transitions use a single screen plane rather than a second HUD/menu overlay.
- Tracked melee strokes send a normal attack for an equipped melee weapon. Head translation,
  tracking jumps and stale samples are rejected. Menus, vehicles and controller mode disable this path.

## Weapon rendering work and remaining issues

The pose adapter preserves consumer-specific inverse binds, named appearance layouts and source palettes.
It uses bounded private GPU copies, recognizes supported scene-depth consumers, and rebases only verified
shader contracts. Readback work is bounded and prioritizes visible hands. The source includes opt-in,
bounded consumer/submission diagnostics for the remaining material problems.

The player confirmed that **mode switching and swing attacks work**, and later reported that the
**extra fingers beside a handgun were resolved**. Detached sleeves, crowbar/melee grip separation and
some scope lenses **remain unresolved in the reported headset tests**. Passing local rendering fixtures
does not establish that these visual problems are fixed in the game. Support spacing, individual reload
visuals and constrained-camera borders retain their earlier limitations.

The tested private installation uses a locally generated weapon/appearance catalog and a matching reload
overlay. Neither is distributed. The generic public fallback builds without the catalog but cannot reproduce
every weapon-specific contact. See [setup and limits](../README.md) and
[the interaction investigation](INTERACTION_2026_11_09.md).

## Performance and account support

The historical M2 result remains **37.1 new game images/s averaged over one 60-second session**.
This update was not remeasured; it does not establish a 45 FPS minimum, an NPU gain, or physical display FPS.
ETFR is disabled: the earlier display-side foveation experiment did not improve FPS in the current pipeline.

Opt-in direct CDPR authentication and cloud-save download/load remain included. Upload roundtrip and
broader save compatibility are unverified. [DIRECT_CLOUD.md](../DIRECT_CLOUD.md) describes private setup.
The English/Japanese READMEs now include the graphics recovery baseline and the community Discord link.

## Local verification

The public source was checked without loading game assets or signing into an account:

```sh
sh tools/check_live_controls.sh
sh tools/check_release_controls.sh
sh tools/check_direct_cloud.sh
make -C shims all mac
sh tools/prepare_test.sh
cd app
xcodegen generate
xcodebuild -project VXMacHost.xcodeproj -scheme VXMacHost -configuration Debug \
  -destination generic/platform=visionOS -derivedDataPath ../build/publish-host \
  CODE_SIGNING_ALLOWED=NO build
```

The host build embeds only the project-owned test program. Checks cover real Metal menu pixels,
32 control-mode roundtrips, release barriers, palette/native-binding restoration, hand/contact state,
and isolated TLS/certificate/browser/account-policy fixtures. The parent development tree's
`make -C VXRuntime check` also passed on retry; the first attempt failed its unrelated fiber-pool
test because the scheduler performed no cross-thread migration.

No built app, game image, shader capture, extracted catalog, compiled reload cache, model weights,
CA bundle, credential, save or raw device log is included. MIT applies to original project source.
