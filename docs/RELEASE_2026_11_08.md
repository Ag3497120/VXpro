# Hand-tracking, performance and camera checkpoint — 2026-11-08

This checkpoint publishes the current source from the accepted M2 Vision Pro installation. It keeps the
hand-tracking branch separate from the standard controller branch on `main`. Historical experiment logs
in this repository record both successful and rejected attempts; this document describes the accepted state.

## Included changes

- ARKit wrist tracking, Joy-Con inputs, right-hand weapon grip, left-hand support and game equipment/ammo bridge.
- Matching manual reload source revision 5, with native vehicle input handling and separate pistol/non-pistol
  chamber policy. The current script does not write FOV overrides. Compile it against your own original game cache.
- Optional embedding of the matching private reload overlay into the signed host, so app and script can be updated
  together. No compiled script cache or game configuration XML is distributed.
- Frame pacing, scheduled warp release, bounded image slots, demand-driven history copying, GPU profiling,
  frame-budget tools and standalone diagnostic app sources. The hand host project uses `VXFP_SLOTS=4` to match
  the accepted installation; the reusable pipeline header keeps its configurable default.
- An immutable camera view/projection tuple stored on the owning Metal command buffer and read once at submission.
  This avoids mixing the rendered image with a later mutable global camera sample. It adds no texture copy or GPU pass.
- Source and numerical-report tools for the NPU/offload/frame-prediction experiments. They are experimental,
  not enabled model acceleration in the accepted setup.

## Remaining issues

- Rectangular image borders during vehicle use and some story conversations/cutscenes.
- Weapon-specific support spacing, sight/scope attachment, reload/slide visuals and barrel-directed shot integration
  still need work or broader validation. The accepted head fix does not claim to resolve every weapon's movement.
- A private catalog generated from the owner's game is required to reproduce all tested weapon contacts.
  Without it the public source compiles with a generic fallback; the extracted catalog is not included.
- Automatic chambering and manual pistol slides depend on the matching script, game version and verified mesh binding.
- Immediate in-game switching between standard controllers and tracked hands is still a future integration requirement.

## Build and tested settings

Use the normal setup guide with your purchased game and your own signing team. Regenerate the Xcode project after
updating sources. The standalone project retains `app/Signing.xcconfig` / git-ignored `app/Local.xcconfig` rather
than the developer's device or signing identity.

[configs/hand-tracking-2026-11-08.args.txt](configs/hand-tracking-2026-11-08.args.txt) records the exact tested
startup flags for `Documents/vxmac_args.txt`. It is an explicit experimental preset, not a replacement for every
player's custom configuration. Its performance controls include:

```text
-env VXMAC_WARP_RELEASE=scheduled
-env VXMAC_PACING=frame
-env VXMAC_GAME_MAX_FPS=45
-env VXMAC_GPU_CAP=0
-env VXMAC_PRESENT_REPEAT=1
-env VXMAC_HISTORY_COPY=demand
```

The cap value is not a measured FPS. Stereo `system` offsets modify depth reprojection; native per-eye hand/weapon
geometry replay is not claimed. Interpolation/NPU models and detailed GPU profiling are not enabled in this preset.
It retains the hand diagnostics used in the accepted installation; private captures are never committed.

For manual reload, use `tools/vxhands_compile_overlay.py --help`. Supply your own unmodified `final.redscripts`,
the `redscript-cli` executable, your original `r6/config` directory through `--manual-config`, a private `--output`
outside the game folder, and `--weapon-bridge`. The helper builds the three-file overlay without editing the input.
Set `VXMAC_RELOAD_OVERLAY` to that private output directory when building the host, or deploy the matching files
to its documented container overlay. Keep all generated game data private.

## Local source checks

These commands build only the project's own shims/test programs; they do not install or launch the game:

```sh
sh tools/check_release_controls.sh
make -C shims -j4 all mac
sh tools/prepare_test.sh
```

The Python source tests use NumPy. The teacher tests additionally require the project's own raster helper:

```sh
mkdir -p build/source-checks
clang -O2 -dynamiclib tools/interp_teacher_raster.c -o build/source-checks/libteacher.dylib
VX_TEACHER_RASTER="$PWD/build/source-checks/libteacher.dylib" python3 -m unittest discover -s tests -p '*_test.py'
```

`tools/fps_report.py HOST.jsonl --summary --seconds 60` works in this standalone repository and labels its output
as an unsealed summary. Sealed collection/validation additionally requires the optional VeRantyx harness.
